# Assumptions / Defaults

- [ ] Default missing-plugin behavior remains `PluginMissingBehavior.RefuseDatabase` (no breaking change).
- [ ] `ValidatePluginsOnOpen` is `bool?` defaulting to `null`. When `null` (default), the effective behavior is disabled (preserves legacy deferred failure). Explicit `true` enables validation-on-open; explicit `false` keeps it disabled regardless of `MissingPluginBehavior`.
- [ ] Missing-plugin modes reduced to two: `RefuseDatabase` and `AllowIfSafe`. `RefuseOperations` is deprecated (`[Obsolete]`) but retained at its original ordinal (`= 1`) for binary compatibility; at runtime it is treated as `AllowIfSafe`.
- [ ] `$plugins` initially reports only plugin-owned indexes (not future plugin assets like arbitrary page allocations).
- [ ] Validation-on-open and `$plugins` scan persisted collection pages using a WAL-aware raw page-buffer reader + a fault-tolerant `TryParse` path; they must not depend on a newly introduced persisted header marker being present (legacy databases exist), and must not go through the normal `Snapshot.GetPage`/`CollectionPage` constructor path.
- [ ] Factory mode (`BuildFactory()`) always shares a single engine/context pair and initializes plugins exactly once for that pair.
- [ ] Factory mode assumes `ILitePlugin.Initialize` is registration-only and plugins do not capture the `LiteDatabase` instance they are initialized with. **This assumption is currently violated by the Spatial plugin** (`SpatialPluginRegistry.Attach` stores `LiteDatabase`, and services/closures can capture it indirectly). This must be resolved before factory mode ships (see Intention.md for options).
- [ ] The same `LiteDatabase` capture constraint applies to `LinqResolverFactory` delegate (currently the Spatial plugin ignores the parameter, but the delegate signature allows capture).
- [ ] Planned change: `IPluginDiagnosticPolicy.MissingBehavior` is deprecated and ignored for enforcement; host-controlled `LiteDatabaseOptions.MissingPluginBehavior` is the source of truth. Current enforcement consults `DiagnosticPolicy.MissingBehavior`; this plan moves the source of truth to `LiteDatabaseOptions` and propagates it via: `LiteDatabaseOptions` → engine (`LiteEngine` field) → `TransactionMonitor` → `Transaction` → `Snapshot`.
- [ ] `IndexType != 0` is the authoritative on-disk marker for plugin-owned indexes. Target enforcement scans `IndexType` directly (current code keys off metadata entries). Note: a single corrupted byte can trigger this. Under strict behavior, a corrupted `IndexType` byte can make the database inaccessible. This is an acceptable trade-off (safety > availability) but should be documented; future work could add corroboration checks.
- [ ] New behavior: plugin disposal follows ownership conventions: factory-created plugins (via `UsePlugin(Func<...>)`) are disposed by the factory/database; instance-supplied plugins (via `UsePlugin(ILitePlugin)`) are NOT disposed (caller owns). Current `LiteDatabase` constructors do not dispose plugins.
- [ ] Builder is single-use and not thread-safe (same convention as `IHostBuilder`).
- [ ] Second data-source call on builder throws `InvalidOperationException` (no "last call wins").
- [ ] `UseFile(...)` + `BuildFactory()` + `ConnectionType.Direct` is safe and recommended. The factory creates ONE engine with exclusive file access; no corruption risk.
- [ ] `Rebuild()` is incompatible with factory mode when multiple handles are active. Must be refused (`InvalidOperationException`) when factory refcount > 1. Factory-level rebuild with exclusive access is deferred to a future iteration.
- [ ] Current bug: `Snapshot._missingPluginWarnings` is process-global (`static`) and keyed only by `pluginId`. This plan scopes it by database identity (e.g., store on `DefaultPluginContext` / engine identity) to avoid cross-database warning suppression and `<unknown>` collisions.
- [ ] Planned change: plugin context registries are frozen (`Freeze()`) after initialization in ALL modes (`Build()` and `BuildFactory()`) to enforce a uniform contract.
- [ ] Planned change: `DiagnosticPolicy` getter/setter use `volatile` or equivalent memory barrier for thread safety in factory mode.
- [ ] Required change: `SharedEngine.OpenDatabase()` must use a local variable for engine construction, only assigning to `_engine` after both construction and `SetPluginContext` succeed (current code assigns `_engine` before `SetPluginContext`). This prevents broken engine references on validation failure.
- [ ] On-disk plugin metadata format has limited version extensibility: the marker byte uses the high bit for legacy/current format and the low 7 bits for `pluginIdLength`. Future versioning likely requires a new marker scheme or an explicit version field in the payload.
- [ ] Phase 1 must include an explicit migration step: search all `RefuseOperations` references in the codebase and map them to `AllowIfSafe` before the enum member is deprecated.
